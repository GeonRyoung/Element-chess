## 1. Business purpose
#### Project background
현대의 네트워크 애플리케이션 및 게임 환경은 기하급수적으로 증가하는 동시 접속자의 방대한 데이터 트래픽을 **지연 없이** 처리해야 하는 중대한 기술적 도전에 직면해 있습니다.  
 최근 5년간의 시장 동향을 살펴보면 글로벌 게임 시장은 단순한 연결을 넘어 **초고주사율 동기화**를 요구하는 대규모 환경으로 진화하고 있으며, 이에 따라 서버가 감당해야 할 네트워크 I/O 부하 역시 전례 없는 수준으로 가중되고 있습니다.그러나 전동적인 'Thread-per-Connection' 모델이나 ```select```, ```poll```과 같은 단순 멀티플렉싱 기법은 접속자 증가에 따른 **컨텍스트 스위칭 오버헤드와 메모리 자원 고갈**이라는 구조적 한계로 인해, 대규모 접속 처리 시 치명적인 성능 저하를 야기합니다.
따라서 **시스템 자원의 효율성을 극대화**하고 초저지연성을 보장하기 위해, Windows 운영체제 커널 수준에서 최적화된 스레드 풀링과 큐일 메커니즘을 제공하는 **비동기 입출력 포트** 기반의 고성능 아키텍처 도입은 현대 고성능 서버 설계에 있어 필연적인 선택이자 핵심적인 기술로 부상하고 있습니다.
#### Goal
이 프로젝트의 최종 목표는 보안성과 게임성을 동시에 갖춘 오토 배틀러 시스템 구축입니다.
- **IOCP 기반 고성능 서버 아키텍처 설계 및 검증**: Windows 커널 수준에서 제공하는 입출력 완료 포트를 채택하여, 최소한의 워커 스레드로 수천 개의 I/O를 병렬 처리하는 고효율 비동기 서버를 구축합니다.
- **대규모 트래픽 수용 능력 확보**: 1000개의 가상 봇(Dummy Client)를 활용하여 초당 수십 회 이상의 상태 동기화 패킷을 생성하고, 이를 지연 없이 처리함으로써 시스템의 안정성과 확장성을 입증합니다.
- **풀스택 관제 시스템 통합**: Prometheus와 Grafana를 연동하여 CPU, 메모리, PPS, 세션 상태 등을 모니터링합니다. 이를 통해 장애 발생 전 임계치 기반의 알람 시스템을 구축하여 서비스 가용성을 높이는 걸 목표로 합니다.
- **RUDP(Reliable UDP) 프로토콜 최적화**:UDP의 속도와 TCP의 신뢰성을 결합한 RUDP 프로토콜을 구현하여, 게임 환경에 최적화된 패킷 전송 효율을 달성합니다.
#### Target Market
- **대규모 멀티플레이어 게임 개발사**: 수천 명의 사용자가 동시에 상호작용해야하는 MMORPG나 배틀로얄 장르의 게임 서버 인프라를 구축하려는 기업이 주 타겟입니다.
- **실시간 데이터 스트리밍 및 관제 솔루션 기업**: 선박 내 배터리 화재 예측 AI 시스템과 같이 대량의 센서 데이터를 실시간으로 수집하고 시각화해야하는 산업 현장의 관제 센터가 해당됩니다,.
- **인프라 비용 최적화가 필요한 스타트업**: 서버 하드웨어의 무분별한 스케일 업 대신 소프트웨어 아키텍처 최적화를 통해 운영 비용을 절감하고자 하는 기술 중심 기업에 핵심적인 가치를 제공합니다.

## 2. System context diagram
![](https://velog.velcdn.com/images/rjsfud/post/c39c57d1-ed73-49f6-8e4c-cfec7d1aa58e/image.png)

- **Player**: 게임을 플레이어하는 유저
- **Client(UE)**: 클라이언트를 렌더링해주는 역할
- **Game Server**: 게임에 필요한 데이터 관련 로직들을 수행해주는 역할
- **Player -> Client**: 마우스 및 키보드를 통한 유저의 게임 조작 입력 전달
- **Client -> Server**: 유닛 구매, 리롤, 배치, 전투 등 서버 검증이 필요한 게임 데이터 전송
- **Server <-> DB**: 게임 진행 데이터의 비동기 저장 및 로드
- **Server -> Client**: 데이터 기반 로직에 따른 결과 전송
- **Client -> Player**: 게임 화면 렌더링 및 결과 제공

## 3. Use case list

| ID | Function | Actor | Description |
| :--- | :--- | :--- | :--- |
| 1 | 계정 로그인 | Player | ID/PW로 로그인을 시도하며 서버는 DB 확인 후 세션을 생성합니다. |
| 2 | 프로필 관리 | Player, Server | 신규 유저 닉네임 생성 및 기존 플레이 데이터를 로드합니다. |
| 3 | 상점 갱신(Reroll) | Player | 재화를 소모하여 유닛 목록을 갱신하거나 필요한 유닛을 탐색합니다. |
| 4 | 유닛 구매 및 판매 | Player, Server | 유닛을 구매하여 보관함에 추가하거나 판매하여 재화를 되돌려 받습니다. |
| 5 | 유닛 진화 처리 | Server | 동일 유닛이 특정 개수 이상 모이면 상위 단계로 자동 합체됩니다. |
| 6 | 유닛 배치 | Player | 전투 필드 내 그리드 영역에 유닛을 배치하거나 위치를 변경합니다. |
| 7 | 라운드 시작 요청 | Player | 정비 단계를 마치고 전투 시작을 위해 서버에 준비 상태를 전달합니다. |
| 8 | 전투 시뮬레이션 | Server, Client | 서버에서 모든 로직을 계산하여 승패를 결정하고 클라이언트는 이를 재생합니다. |
| 9 | 전투 결과 동기화 | Server, Client | 라운드 종료 후 체력 상태, 승패, 보상 정보를 클라이언트에 전송합니다. |
| 10 | 진행도 저장 | Server | 라운드 정보와 유저 데이터를 DB에 기록하여 데이터 유실을 방지합니다. |

## 4. Concept of operation

| Function | Purpose | Approach | Dynamics | Goals |
| :--- | :--- | :--- | :--- | :--- |
| **계정 로그인** | 사용자 정보 확인 | ID/PW 해싱 전송 후 서버 DB 비교 검증 | 앱 실행 및 로그인 시도 시 | 허가된 사용자 접속 제한 및 데이터 로드 |
| **프로필 관리** | 유저 정보 정의 및 관리 | DB 내 프로필 존재 확인 후 신규 생성 또는 로드 | 로그인 성공 직후 | 유저별 고유 정보 확립 |
| **상점 갱신** | 유닛 획득 기회 제공 | 서버 랜덤 목록 결정 후 전송, 재화 차감 검증 | 준비 단계 상점 UI 조작 시 | 유닛 등장 기준 마련 및 재화 소모 |
| **유닛 구매/판매** | 유닛 구성 및 재화 관리 | 클라이언트 요청을 서버가 검증 후 정보 업데이트 | 준비 단계 구매/판매 클릭 시 | 서버 데이터 기반의 안정적인 자산 관리 |
| **유닛 진화 처리** | 유닛 성장 및 강화 | 서버 인벤토리 실시간 감시 후 등급 업 패킷 전송 | 유닛 구매로 데이터 변경 시 | 자동화된 성장 시스템 및 성취감 제공 |
| **유닛 배치** | 진형 선택 및 위치 지정 | 그리드 좌표 전송 후 서버에서 이동 가능 여부 판정 | 준비 단계 필드 유닛 조작 시 | 클라이언트-서버 위치 동기화 및 데이터 확보 |
| **라운드 시작** | 전투 상태 전환 및 진행 | 준비 완료 신호 수집 후 전투 페이즈 패킷 전송 | 준비 완료 또는 제한 시간 만료 시 | 정해진 시간 내 유동적인 흐름 조정 |
| **전투 시뮬레이션** | 공정한 승패 결과 도출 | 서버 독립 연산 루프 구동으로 서버 제어 구조 유지 | 라운드 시작 직후 | 클라이언트 치트 방지 및 서버 검증 |
| **전화 결과 동기화** | 시각적 연출 및 정보 제공 | 시뮬레이션 종료 즉시 결과 패킷 전송 및 로직 재현 | 서버 내 전투 시뮬레이션 종료 시 | 서버-클라이언트 동일 결과로 무결성 증명 |
| **진행도 저장** | 데이터 보존 및 복구 지원 | 서버 메모리 데이터를 비동기 방식으로 DB에 기록 | 결과 동기화 완료 또는 정보 변경 시 | 서버 장애 시에도 데이터 손실 최소화 |

## 5. Problem statement
**Problems**
- **서버 클라이언트 동기화 오차**: 서버 로직 수행 시간과 클라이언트 연출 사이의 시간차를 최소화한다.
- **데이터 무결성**: 클라이언트 조작을 방지하기 위해 모든 주요 로직은 서버에서 검증된다.

**NFRs**
- 모든 서버 패킷 처리는 100ms 이내에 완료되어야한다.
- IOCP 구조를 통해 최소 1000명의 동시 접속을 수용해야한다.

## 6. Glossary
- **IOCP**: Windosw에서 대규모 클라이언트를 효율적으로 처리하기 위한 비동기 I/O 매커니즘
- **Unreal**: 클라이언트를 제작을 도와주는 툴
