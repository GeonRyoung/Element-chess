## 1. Introduction
#### Summary
본 문서는 고성능 비동기 네트워크 서버 아키텍어와 실시간 모니터링 시스템을 통합한 프로젝트의 분석 결과를 기술한다. 본 프로젝트는 현대 소프트웨어 설계에서 필수적인 동시성 처리, 신뢰성, 가시성을 확보하는 것을 핵심 목적으로 한다.
Conceptualization 단계에서 정의된 요구사항을 바탕으로 유스케이스 및 도메인 모델을 구체화하여 시스템의 실질적인 구현 기반을 마련한다.

#### Introduce
- **고성능 비동기 엔진**: Windows 운영체제에서 제공하는 비동기 입출력 모델인 IOCP를 아키텍처의 근간으로 삼는다. 이를 통해 스레드 컨텍스트 오버헤드를 최소화하고, 수천 개의 동시 접속 세션을 적은 리소스로 효율적으로 제어한다.
- **RUDP**: UDP의 속도를 유지하면서 애플리케이션 레벨에서 Selective Repeat ARQ 알고리즘을 적용한 RUDP 매커니즘을 도입한다. 이는 TCP의 고질적인 문제인 전송 지연을 회피하면서 중요 데이터의 무결성을 보장한다.
- **실시간 모니터링**:  Prometheus와 Grafana를 연동하여 서버의 내부 성능 지표를 실시가능로 수집하고 시각화한다.

#### Business Goals
- **산업적 활용성**: 수만 명의 사용자가 상호작용하는 대규모 온라인 게임서버는 물론, 짧은 지연 시간과 무결성이 요구되는 금융 거래, 대규모 IoT 디바이스 서버에 즉각적으로 적용할 수 있는 유용성을 갖춘다.
- **기술적 확장성**: 본 시스템에서 구축한 네트워크 모델은 향후 분산 서버 아키텍처로의 확장 및 클라우드 네이티브 환경으로의 이전을 위한 표준 기반 기술 작동을 목표로 한다.

## 2. Use Case Analysis
### 2.1 Use Case Diagram
시스템의 전체적인 기능적 요구사항과 외부 액터 간의 상호작용을 나타내는 유스케이스 다어그램이다. 본 시스템은 고성능 네트워크 엔진의 특성에 맞춰 부하 발생 주체와 시스템 관리 주체를 명확히 분리하여 설계되었다.

#### Actor
- **Dummy Client**: 시스템의 주된 트래픽 소스이다. 실제 유저의 네트워크 행동 패턴을 시뮬레이션하여 서버의 I/O 및 로직 처리 성능을 한계치까지 유도하는 능동적 액터이다.
- **Admin**: 시스템의 운영 상태를 분석하는 관찰자이다. Grafana와 Prometheus를 매개체로 하여 서버의 정량적 지표를 모니터링하고, 필요 시 장애 시뮬레이션 등을 통해 시스템의 견고성을 검증하는 분석적 역학을 수행한다.

#### Relationship, Functional Grouping
- **Dummy Client**: 더미 클라이언트는 ID-01(접속 및 인증)을 시작으로 ID-02(위치 업데이트), ID-03(전투 동기화) 등 서버의 비즈니스 로직을 직접적으로 구동시킨다.
- **Admin**: 관리자는 ID-06(메트릭 노출)부터 ID-08(임계치 알람)에 이르는 데이터 파이프라인을 통해 시스템의 상태를 인지한다.

## 3. Domain Analysis

시스템의 아키텍처를 구성하는 핵심 도메인 클래스들을 식별하고, 각 클래스의 역할, 책임, 그리고 다른 클래스와의 연관 관계를 상세히 분석한다. 본 시스템은 고성능 처리를 위해 객체 지향적 설계 원칙과 시스템 프로그래밍 기법이 결합된 형태를 보인다..

1) **IocpCore**
- **역할 및 책임**: Windows 비동기 I/O의 심장부입니다. CreateIoCompletionPort API를 통해 IOCP 커널 객체를 생성하고, CPU 코어 수에 최적화된 개수의 워커 스레드 풀을 생성 및 관리합니다. 네트워크 소켓과 IOCP 객체를 연결하고, GetQueuedCompletionStatus 함수를 호출하여 완료된 I/O 이벤트를 대기하다가 적절한 세션 객체로 디스패치하는 라우팅 책임을 집니다.
- **주요 관계**: 다수의 RudpSession 객체와 연관되며, 스레드 관리를 위해 내부적으로 std::thread 컨테이너를 소유합니다.

2) **RudpSession**
- **역할 및 책임**: 연결된 개별 클라이언트의 상태와 통신 컨텍스트를 유지하는 클래스입니다. 기본 UDP 소켓 위에 신뢰성을 부여하기 위해 RUDP 프로토콜 스택을 구현합니다. 송수신 Sequence Number 관리, ACK 비트맵 처리, 슬라이딩 윈도우 기반의 흐름 제어, 패킷 조립 및 분할 로직을 캡슐화합니다.
- **주요 관계**: IocpCore에 의해 호출되며, 패킷 처리를 위해 PacketHandler를 참조합니다. 재사용을 위해 ObjectPool<RudpSession>에 의해 관리됩니다.

3) **PacketHandler**
- **역할 및 책임**: RudpSession에서 조립이 완료된 온전한 패킷을 전달받아, 패킷 헤더의 Opcode를 분석하고 적절한 비즈니스 로직 함수로 분기하는 라우터 역할을 합니다. 이동, 공격, 채팅 등 다양한 패킷 타입에 대한 처리 핸들러 함수들이 매핑되어 있습니다.
- **주요 관계**: RudpSession으로부터 데이터를 수신하고, 로직 처리를 위해 World 및 Sector 객체에 접근합니다.

4) **World**
- **역할 및 책임**: 게임 서버의 전체 가상 공간과 글로벌 상태를 관리하는 최상위 컨테이너 클래스입니다. 전체 접속 유저의 목록을 관리하고, 공간 분할을 위해 전체 맵을 다수의 Sector 객체로 나누어 소유합니다. 글로벌 공지사항 브로드캐스트나 전체 월드 틱 업데이트를 담당합니다.
- **주요 관계**: 다수의 Sector 객체를 Composition 관계로 포함하며, 전체 RudpSession에 대한 참조를 유지합니다.

5) **Sector**
- **역할 및 책임**: 공간 분할 기법의 기본 단위가 되는 격자 클래스입니다. 자신 영역 내에 위치한 플레이어 및 NPC 객체들의 목록을 관리합니다. 특정 플레이어가 이동하거나 액션을 취할 때, 전체 월드를 순회하는 대신 해당 Sector와 인접한 8개 Sector 내의 객체들에게만 패킷을 브로드캐스트하도록 하여 $O(N^2)$의 동기화 복잡도를 $O(N)$에 가깝게 최적화하는 핵심 책임을 집니다.
- **주요 관계**: World에 속해 있으며, 영역 내의 RudpSession 목록을 관리합니다.

6) **BotManager**
- **역할 및 책임**: 서버의 부하 테스트를 위해 수천 개의 Dummy Client 인스턴스를 생성, 구동, 소멸시키는 관리자 클래스입니다. 각 봇들에게 고유한 행동 패턴을 부여하고, 주기적으로 봇들의 상태를 업데이트하여 서버로 패킷을 전송하도록 스케줄링합니다.
- **주요 관계**: 다수의 Dummy Client 객체를 생성하고 생명주기를 관리합니다.

7) **MetricManager**
- **역할 및 책임**: 서버 내부의 다양한 성능 지표를 수집하고 외부로 노출하는 관측 가능성 클래스입니다. prometheus-cpp 라이브러리를 래핑하여 구현되며, Lock-free 카운터나 원자적 변수를 사용하여 메트릭 수집 시 발생하는 동기화 오버헤드를 최소화합니다. 수집된 데이터는 HTTP Exporter를 통해 Prometheus 서버가 스크랩할 수 있도록 제공됩니다.
- **주요 관계**: 시스템 전역에서 싱글톤 패턴으로 접근되어 각 모듈로부터 지표 데이터를 수집합니다.

8) **TimerWheel**
- **역할 및 책임**: 수만 개의 타이머 이벤트를 $O(1)$에 가까운 시간 복잡도로 등록, 취소, 만료 처리하기 위한 고성능 타이머 자료구조 클래스입니다. RUDP의 패킷 재전송 타임아웃, 세션 Heartbeat 체크, 스킬 쿨타임 등 서버 내에서 발생하는 대량의 시간 기반 이벤트를 효율적으로 스케줄링합니다.
- **주요 관계**: RudpSession이 재전송 타이머를 등록할 때 주로 사용되며, 별도의 타이머 스레드에 의해 주기적으로 틱이 진행됩니다.

9) **ObjectPool<T>**
- **역할 및 책임**: 객체의 빈번한 동적 할당 및 해제로 인한 OS 레벨의 메모리 할당 오버헤드와 메모리 단편화를 방지하기 위한 템플릿 기반의 메모리 풀 클래스입니다. 시스템 시작 시 미리 대량의 객체 덩어리를 할당해 두고, 요청 시 풀에서 꺼내어 주며, 사용 완료 시 다시 풀로 반환받습니다. 멀티스레드 환경에서 안전하게 동작하도록 Lock-free 스택/큐 또는 TLS 기법을 활용하여 구현됩니다.
- **주요 관계**: RudpSession, Packet 등 생성/소멸 주기가 짧고 빈번한 객체들의 생명주기를 관리합니다.

10) **Packet**
- **역할 및 책임**: 네트워크를 통해 송수신되는 데이터의 논리적, 물리적 캡슐화 단위입니다. 패킷의 총 길이, Opcode, Sequence Number 등을 포함하는 고정 크기의 Header 영역과, 실제 비즈니스 데이터가 직렬화되어 들어가는 가변 크기의 Payload 영역으로 구성됩니다. 버퍼 오버플로우 방지 및 직렬화/역직렬화 유틸리티 메서드를 제공합니다.
- **주요 관계**: ObjectPool<Packet>에 의해 관리되며, RudpSession과 PacketHandler 사이에서 데이터를 운반하는 매개체 역할을 하는 DTO 역할을 합니다.

## 4 User Interface Prototype

고성능 백엔드 서버 시스템으로 일반 사용자를 위한 GUI 클라이언는 존재하지 않는다. 대신 시스템의 개발, 운영, 모니터링을 담당하는 관리자 및 개발자를 위한 세 가지 핵심 인터페이스(Grafana 대시보드, Server Console, Dummy Client CLI)를 설계한다.

### 4.1 Admin용 Grafana 대시보드 (Element-Pulse System Dashboard)

그림 4-1은 관리자가 서버의 건강 상태와 네트워크 성능을 실시간으로 파악하기 위한 Grafana 대시보드의 프로토타입이다. 각 지표는 논리적인 그룹으로 분류되어 배치된다.
<img width="1024" height="559" alt="image" src="https://github.com/user-attachments/assets/5ca1a183-a101-490c-b342-66648332b6ef" />
* **Global Metrics (상단)**: 시스템의 전체적인 가동 상태를 요약하여 보여준다. 현재 서버에 접속 중인 활성 세션을 게이지 형태로 표시하며, 서버 가동 후 처리된 총 패킷 수와 업타임을 숫자로 나타낸다.
* **Network Performance (중앙)**: 실시간 트래픽 추이를 분석한다. 초당 패킷 수를 선 그래프로 시각화하여 트래픽 스파이크를 감지하며, 특히 RUDP 재전송률이 임계치를 초과할 경우 그래프 색상을 붉은색으로 변경하여 관리자에게 시각적 경고를 제공한다.
* **System Resource (하단)**: 서버의 물리적 자원 사용량을 모니터링한다. IOCP 워커 스레드별 CPU 점유율을 통해 부하 분산 상태를 확인하고, 메모리 풀의 잔여 용량을 확인하여 자원 고갈 위험을 사전에 방지한다.

### 4.2 Server Console UI

그림 4-2는 서버 애플리케이션 실행 시 관리자 터미널에 출력되는 텍스트 기반의 실시간 로그 인터페이스이다. 시스템의 부팅 과정과 주요 성능 통계, 예외 상황을 표준 출력으로 제공한다.

<img width="1570" height="701" alt="image" src="https://github.com/user-attachments/assets/02a3e7f8-3551-4327-a40e-8acf403e0525" />

* **부팅 시퀀스 로그**: 설정 파일 로드, 메모리 풀 초기화, 워커 스레드 생성, 포트 바인딩 등 서버 구동의 각 단계별 성공 여부를 [INFO] 탭을 통해 출력한다.
* **주기적 상태 출력**: 서버가 정상 가동되면 5분 주기로 현재 활성 세션 수와 PPS, 재전송률 등 핵심 지표를 요약하여 출력함으로써 대시보드 없이도 서버 상태를 즉각 파악할 수 있게 한다.
* **경고 및 에러 로그**: 네트워크 타임아웃이나 비정상 세션 종료 발생 시 [WARN] 또는 [ERROR] 태그와 함께 해당 세션 ID를 출력하여 관리자의 빠른 대응을 돕는다.

### 4.3 Dummy Client 제어 CLI

그림 4-3은 부하 테스트를 수행하는 개발자가 가상 봇의 동작을 동적으로 제어하기 위해 사용하는 대화형 커맨드 라인 인터페이스이다.

<img width="1634" height="710" alt="image" src="https://github.com/user-attachments/assets/70fdf56e-8c66-43d9-b759-a228f4a46000" />

* **봇 생성 및 연결**: `start_bots` 명령을 통해 수천 개의 가상 봇을 동시에 서버에 접속시킬 수 있으며, 접속 지연 시간 옵션을 통해 순간 부하 강도를 조절할 수 있다.
* **네트워크 장애 주입**: `set_packet_loss` 명령을 사용하여 인위적인 패킷 손실률을 설정한다. 이는 열악한 네트워크 환경에서의 서버 복구 능력을 테스트하는 핵심 수단이 된다.
* **시나리오 실행**: `run_scenario` 명령을 통해 봇들이 특정 구역으로 집결하거나 특정 공격 패턴을 취하게 하는 등 FSM 기반의 복합적인 부하 테스트를 트리거한다.
* **실시간 상태 조회**: `status` 명령으로 가상 봇들이 인지하는 평균 지연 시간과 실제 전송된 패킷의 통계치를 확인하여 서버의 성능 목표 달성 여부를 검증한다.

## 5. Glossary 
- **IOCP**: Windows 운영체제에서 제공하는 가장 효율적인 비동기 I/O 통지 모델. 다수의 I/O 작업을 소수의 스레드 풀을 통해 처리할 수 있게 하여 컨텍스트 스위칭 비용을 극적으로 낮춘다.
- **RUDP**: 기본적으로 신뢰성을 보장하지 않는 UDP 프로토콜 위에, 애플리케이션 레벨에서 순서 보장 및 재전송 로직을 추가하여 TCP와 유사한 신뢰성을 제공하면서도 전송 지연을 최소화한 커스텀 프로토콜
- **Seletive Repeat ARQ**: 패킷 유실 발생 시, 수신 측에서 정상적으로 받은 패킷은 버퍼에 보관하고 유실된 특정 패킷만을 송신 측에 재전송 요구하는 오류 제어 방식
- **공간 분할**: 넓은 2D/3D 가상 공간을 일정한 크기의 격자나 트리구조로 나누어, 객체 간의 충돌 검사나 네트워크 패킷 브로드캐스트 대상을 인접한 영역으로 한정 지어 연산량을 줄이는 최적화 기법
