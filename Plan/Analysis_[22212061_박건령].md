## 1\. Introduction

#### Summary

본 문서는 고성능 비동기 네트워크 서버 아키텍어와 실시간 모니터링 시스템을 통합한 프로젝트의 분석 결과를 기술한다. 본 프로젝트는 현대 소프트웨어 설계에서 필수적인 동시성 처리, 신뢰성, 가시성을 확보하는 것을 핵심 목적으로 한다.  
Conceptualization 단계에서 정의된 요구사항을 바탕으로 유스케이스 및 도메인 모델을 구체화하여 시스템의 실질적인 구현 기반을 마련한다.

#### Introduce

-   **고성능 비동기 엔진**: Windows 운영체제에서 제공하는 비동기 입출력 모델인 IOCP를 아키텍처의 근간으로 삼는다. 이를 통해 스레드 컨텍스트 오버헤드를 최소화하고, 수천 개의 동시 접속 세션을 적은 리소스로 효율적으로 제어한다.
-   **RUDP**: UDP의 속도를 유지하면서 애플리케이션 레벨에서 Selective Repeat ARQ 알고리즘을 적용한 RUDP 매커니즘을 도입한다. 이는 TCP의 고질적인 문제인 전송 지연을 회피하면서 중요 데이터의 무결성을 보장한다.
-   **실시간 모니터링**: Prometheus와 Grafana를 연동하여 서버의 내부 성능 지표를 실시가능로 수집하고 시각화한다.

#### Business Goals

-   **산업적 활용성**: 수만 명의 사용자가 상호작용하는 대규모 온라인 게임서버는 물론, 짧은 지연 시간과 무결성이 요구되는 금융 거래, 대규모 IoT 디바이스 서버에 즉각적으로 적용할 수 있는 유용성을 갖춘다.
-   **기술적 확장성**: 본 시스템에서 구축한 네트워크 모델은 향후 분산 서버 아키텍처로의 확장 및 클라우드 네이티브 환경으로의 이전을 위한 표준 기반 기술 작동을 목표로 한다.

#### Actor

-   **Dummy Client**: 시스템의 주된 트래픽 소스이다. 실제 유저의 네트워크 행동 패턴을 시뮬레이션하여 서버의 I/O 및 로직 처리 성능을 한계치까지 유도하는 능동적 액터이다.
-   **Admin**: 시스템의 운영 상태를 분석하는 관찰자이다. Grafana와 Prometheus를 매개체로 하여 서버의 정량적 지표를 모니터링하고, 필요 시 장애 시뮬레이션 등을 통해 시스템의 견고성을 검증하는 분석적 역학을 수행한다.

#### Relationship, Functional Grouping

-   **Dummy Client**: 더미 클라이언트는 ID-01(접속 및 인증)을 시작으로 ID-02(위치 업데이트), ID-03(전투 동기화) 등 서버의 비즈니스 로직을 직접적으로 구동시킨다.
-   **Admin**: 관리자는 ID-06(메트릭 노출)부터 ID-08(임계치 알람)에 이르는 데이터 파이프라인을 통해 시스템의 상태를 인지한다.

## 3\. Domain Analysis

시스템의 아키텍처를 구성하는 핵심 도메인 클래스들을 식별하고, 각 클래스의 역할, 책임, 그리고 다른 클래스와의 연관 관계를 상세히 분석한다. 본 시스템은 고성능 처리를 위해 객체 지향적 설계 원칙과 시스템 프로그래밍 기법이 결합된 형태를 보인다. 설계 단계에서 구체화된 18종의 핵심 도메인 모델을 기준으로 시스템의 정적 구조를 정의한다.

1.  **IocpCore**

-   **역할 및 책임**: Windows 비동기 I/O의 심장부이자 전역 엔진 관리자(Singleton)이다. `CreateIoCompletionPort` API를 통해 IOCP 커널 객체를 생성하고, CPU 코어 수에 최적화된 워커 스레드 풀을 관리한다. 네트워크 소켓을 IOCP에 바인딩하고 비동기 이벤트를 대기하다가 적절한 세션으로 디스패치하는 책임을 진다.
-   **주요 관계**: `SessionManager`에 대한 소유권을 가지며, 다수의 워커 스레드를 내부적으로 관리한다.

2.  **SessionManager**

-   **역할 및 책임**: 동시 접속하는 클라이언트 세션의 생성, 조회, 소멸 등 전체 생명주기를 전담하여 관리한다. 멀티스레드 환경에서 안전하게 세션을 관리하기 위해 다중 읽기/단일 쓰기(Shared Lock) 메커니즘을 활용하며, 메모리 풀과 연계하여 세션 객체를 할당/회수한다.
-   **주요 관계**: 다수의 `RudpSession` 객체를 Map 구조로 관리하며, `LockFreeObjectPool<RudpSession>`에 의존한다.

3.  **RudpSession**

-   **역할 및 책임**: 연결된 개별 클라이언트의 상태와 통신 컨텍스트를 유지한다. 기본 UDP 소켓 위에 신뢰성을 부여하기 위해 RUDP 프로토콜 스택(송수신 Sequence Number 관리, 재전송 처리)을 구현한다.
-   **주요 관계**: `IocpCore`에 의해 등록되며, 파편화된 데이터 처리를 위해 `CircularBuffer`를 소유하고 `TimerWheel`을 통해 재전송 타이머를 예약한다.

4.  **CircularBuffer**

-   **역할 및 책임**: 네트워크 계층에서 수신된 파편화된 바이트 스트림을 임시 저장하고 안전하게 온전한 패킷으로 조립하기 위한 버퍼 관리 자료구조이다.
-   **주요 관계**: `RudpSession` 내부에 종속되어 세션별 수신 데이터 스트림 조립 역할을 수행한다.

5.  **PacketDispatcher**

-   **역할 및 책임**: 조립이 완료된 패킷의 헤더(Opcode)를 분석하여 적절한 비즈니스 로직(Job)으로 분기하는 라우터 역할을 수행한다. 전략 패턴을 통해 개방-폐쇄 원칙(OCP)을 준수하여 새로운 패킷 타입 확장을 용이하게 한다.
-   **주요 관계**: `RudpSession`으로부터 패킷을 전달받아 `JobQueue`에 처리 작업을 스레드 세이프하게 삽입한다.

6.  **JobQueue**

-   **역할 및 책임**: 네트워크 I/O 스레드와 게임 로직 스레드 간의 작업을 비동기적으로 전달하는 스레드 세이프(Thread-safe) 워크 큐이다. 동기화 락과 조건 변수(Condition Variable)를 사용하여 스레드 간의 안전한 대기 및 깨움을 제어한다.
-   **주요 관계**: 네트워크 계층(`PacketDispatcher` 등)이 생산자(Producer) 역할을, `GameLogic`이 소비자(Consumer) 역할을 수행한다.

7.  **IExecutionService**

-   **역할 및 책임**: 특정 실행 문맥(Context)에 종속되지 않고 비즈니스 작업을 수행하도록 정의하는 추상화 인터페이스이다. 의존성 역전 원칙(DIP)을 적용하여 네트워크 계층이 구체적인 로직 구현체에 결합되지 않도록 분리한다.
-   **주요 관계**: `GameLogic` 클래스가 이 인터페이스를 상속받아 실제 로직 큐 삽입 기능을 구현한다.

8.  **GameLogic**

-   **역할 및 책임**: 서버의 메인 비즈니스 로직과 시뮬레이션 틱(Tick)을 전담하여 처리하는 실행자이다. `JobQueue`에 누적된 패킷 이벤트와 내부 콜백 작업들을 추출하여 일괄 처리하고 월드의 상태를 갱신한다.
-   **주요 관계**: 내부적으로 `JobQueue`를 소유하며, 전역 상태인 `World` 객체에 접근하여 게임의 물리/논리적 상태를 변화시킨다.

9.  **World**

-   **역할 및 책임**: 게임 서버의 전체 가상 공간과 글로벌 상태를 관리하는 최상위 컨테이너이다. 월드 내 모든 엔티티를 전역 ID로 관리하며, 공간 분할 처리를 위해 월드를 다수의 Sector 격자로 나누어 관리한다.
-   **주요 관계**: 다수의 `Sector` 객체 및 `Entity` 객체에 대한 소유권 및 관리 책임을 가진다.

10.  **Sector**

-   **역할 및 책임**: 공간 분할 기법의 기본 단위가 되는 국소 공간(2D 격자) 클래스이다. 자신 영역 내에 위치한 엔티티들의 목록을 관리하며, 시야 반경(AOI) 내에 있는 주변 액터들에게만 선별적으로 패킷을 브로드캐스트하여 $O(N^2)$의 연산 비용을 최적화한다.
-   **주요 관계**: `World`에 속해 있으며, 해당 물리적 영역 내에 진입/이탈하는 `Entity`들의 목록을 보호하고 갱신한다.

11.  **Entity (Abstract)**

-   **역할 및 책임**: 월드 내에 존재하는 모든 동적 객체의 공통된 특성(고유 ID, 2D 좌표, 현재 소속 섹터 등)을 정의하는 추상 기본 클래스이다. 개별 상태 변경 시의 무결성을 보장하기 위한 자체 락(Lock) 매커니즘을 포함한다.
-   **주요 관계**: `Player` 및 `Bot` 클래스의 부모 클래스이며, 순환 참조를 방지하기 위해 현재 위치한 `Sector`를 약한 참조(weak\_ptr)로 유지한다.

12.  **Player**

-   **역할 및 책임**: 실제 네트워크 클라이언트와 1:1로 매핑되는 유저 엔티티이다. 클라이언트의 입력을 바탕으로 이동 검증 및 고유 로직을 수행하며 결과를 다시 클라이언트로 송신한다.
-   **주요 관계**: `Entity`를 상속하며, 실제 패킷 통신을 위해 `RudpSession`에 대한 약한 참조를 가진다.

13.  **Bot**

-   **역할 및 책임**: 서버 부하 테스트를 위해 실제 유저처럼 동작하는 더미 클라이언트 엔티티이다. 유한 상태 기계(FSM) 알고리즘을 내장하여 배회, 추적, 대기 등 상태에 따른 자율적인 행동 판단 및 패킷 전송 로직을 수행한다.
-   **주요 관계**: `Entity`를 상속하며, 자체적인 인공지능 틱(Tick) 주기에 따라 행동을 결정한다.

14.  **BotManager**

-   **역할 및 책임**: 성능 테스트 시뮬레이션을 위해 수천 개의 Dummy Client(Bot) 인스턴스를 생성, 구동, 소멸시키는 중앙 관리자이다. 봇의 일괄 생성 및 월드 진입을 스케줄링한다.
-   **주요 관계**: 다수의 `Bot` 객체를 컨테이너로 소유하고 동기화 락을 통해 생명주기를 안전하게 관리한다.

15.  **TimerWheel**

-   **역할 및 책임**: RUDP 재전송 타임아웃, 세션 Heartbeat 등 수만 개의 시간 기반 예약 이벤트를 환형 배열(Wheel) 구조를 통해 $O(1)$의 비용으로 스케줄링하고 만료 처리하는 고성능 타이머 객체이다.
-   **주요 관계**: `RudpSession`으로부터 재전송 콜백 등을 등록받으며, 엔진 틱에 맞춰 만료된 작업을 `JobQueue`로 밀어 넣는다.

16.  **MetricManager**

-   **역할 및 책임**: 서버 내부의 성능 지표(PPS, Latency 등)를 락프리(Lock-free) 방식으로 수집하고 외부 모니터링 서버(Prometheus)가 읽어갈 수 있도록 JSON 등의 포맷으로 직렬화하여 노출하는 관측 가능성 클래스이다.
-   **주요 관계**: 네트워크 및 로직 계층 전역에서 호출되어 지표를 수집하며 모니터링 환경의 엔드포인트를 제공한다.

17.  **LockFreeObjectPool**

-   **역할 및 책임**: 객체의 빈번한 동적 할당 및 해제로 인한 메모리 단편화 및 커널 락 오버헤드를 방지하는 메모리 풀이다. CAS(Compare-And-Swap) 알고리즘을 기반으로 ABA 문제를 해결하여 스레드 안전하게 유휴 객체를 재사용한다.
-   **주요 관계**: 생성/소멸이 매우 빈번한 `RudpSession` 및 `Packet` 클래스 객체들을 관리한다.

18.  **Packet**

-   **역할 및 책임**: 네트워크를 통해 송수신되는 실제 데이터의 캡슐화 단위이다. Opcode, 데이터 길이 등을 담는 구조체 형태의 Header와 실제 게임 로직 데이터가 직렬화되는 가변 크기의 Payload 영역으로 구성된다.
-   **주요 관계**: 네트워크 계층과 로직 계층 사이에서 템플릿 기반 직렬화/역직렬화 기능을 제공하며 DTO(Data Transfer Object)로 기능한다.

## 4 User Interface Prototype

고성능 백엔드 서버 시스템으로 일반 사용자를 위한 GUI 클라이언는 존재하지 않는다. 대신 시스템의 개발, 운영, 모니터링을 담당하는 관리자 및 개발자를 위한 세 가지 핵심 인터페이스(Grafana 대시보드, Server Console, Dummy Client CLI)를 설계한다.

### 4.1 Admin용 Grafana 대시보드 (Element-Pulse System Dashboard)

그림 4-1은 관리자가 서버의 건강 상태와 네트워크 성능을 실시간으로 파악하기 위한 Grafana 대시보드의 프로토타입이다. 각 지표는 논리적인 그룹으로 분류되어 배치된다.  
![image](https://github.com/user-attachments/assets/5ca1a183-a101-490c-b342-66648332b6ef)

-   **Global Metrics (상단)**: 시스템의 전체적인 가동 상태를 요약하여 보여준다. 현재 서버에 접속 중인 활성 세션을 게이지 형태로 표시하며, 서버 가동 후 처리된 총 패킷 수와 업타임을 숫자로 나타낸다.
-   **Network Performance (중앙)**: 실시간 트래픽 추이를 분석한다. 초당 패킷 수를 선 그래프로 시각화하여 트래픽 스파이크를 감지하며, 특히 RUDP 재전송률이 임계치를 초과할 경우 그래프 색상을 붉은색으로 변경하여 관리자에게 시각적 경고를 제공한다.
-   **System Resource (하단)**: 서버의 물리적 자원 사용량을 모니터링한다. IOCP 워커 스레드별 CPU 점유율을 통해 부하 분산 상태를 확인하고, 메모리 풀의 잔여 용량을 확인하여 자원 고갈 위험을 사전에 방지한다.

### 4.2 Server Console UI

그림 4-2는 서버 애플리케이션 실행 시 관리자 터미널에 출력되는 텍스트 기반의 실시간 로그 인터페이스이다. 시스템의 부팅 과정과 주요 성능 통계, 예외 상황을 표준 출력으로 제공한다.

![image](https://github.com/user-attachments/assets/02a3e7f8-3551-4327-a40e-8acf403e0525)

-   **부팅 시퀀스 로그**: 설정 파일 로드, 메모리 풀 초기화, 워커 스레드 생성, 포트 바인딩 등 서버 구동의 각 단계별 성공 여부를 \[INFO\] 탭을 통해 출력한다.
-   **주기적 상태 출력**: 서버가 정상 가동되면 5분 주기로 현재 활성 세션 수와 PPS, 재전송률 등 핵심 지표를 요약하여 출력함으로써 대시보드 없이도 서버 상태를 즉각 파악할 수 있게 한다.
-   **경고 및 에러 로그**: 네트워크 타임아웃이나 비정상 세션 종료 발생 시 \[WARN\] 또는 \[ERROR\] 태그와 함께 해당 세션 ID를 출력하여 관리자의 빠른 대응을 돕는다.

### 4.3 Dummy Client 제어 CLI

그림 4-3은 부하 테스트를 수행하는 개발자가 가상 봇의 동작을 동적으로 제어하기 위해 사용하는 대화형 커맨드 라인 인터페이스이다.

![image](https://github.com/user-attachments/assets/70fdf56e-8c66-43d9-b759-a228f4a46000)

-   **봇 생성 및 연결**: `start_bots` 명령을 통해 수천 개의 가상 봇을 동시에 서버에 접속시킬 수 있으며, 접속 지연 시간 옵션을 통해 순간 부하 강도를 조절할 수 있다.
-   **네트워크 장애 주입**: `set_packet_loss` 명령을 사용하여 인위적인 패킷 손실률을 설정한다. 이는 열악한 네트워크 환경에서의 서버 복구 능력을 테스트하는 핵심 수단이 된다.
-   **시나리오 실행**: `run_scenario` 명령을 통해 봇들이 특정 구역으로 집결하거나 특정 공격 패턴을 취하게 하는 등 FSM 기반의 복합적인 부하 테스트를 트리거한다.
-   **실시간 상태 조회**: `status` 명령으로 가상 봇들이 인지하는 평균 지연 시간과 실제 전송된 패킷의 통계치를 확인하여 서버의 성능 목표 달성 여부를 검증한다.

## 5\. Glossary

-   **IOCP**: Windows 운영체제에서 제공하는 가장 효율적인 비동기 I/O 통지 모델. 다수의 I/O 작업을 소수의 스레드 풀을 통해 처리할 수 있게 하여 컨텍스트 스위칭 비용을 극적으로 낮춘다.
-   **RUDP**: 기본적으로 신뢰성을 보장하지 않는 UDP 프로토콜 위에, 애플리케이션 레벨에서 순서 보장 및 재전송 로직을 추가하여 TCP와 유사한 신뢰성을 제공하면서도 전송 지연을 최소화한 커스텀 프로토콜
-   **Seletive Repeat ARQ**: 패킷 유실 발생 시, 수신 측에서 정상적으로 받은 패킷은 버퍼에 보관하고 유실된 특정 패킷만을 송신 측에 재전송 요구하는 오류 제어 방식
-   **공간 분할**: 넓은 2D/3D 가상 공간을 일정한 크기의 격자나 트리구조로 나누어, 객체 간의 충돌 검사나 네트워크 패킷 브로드캐스트 대상을 인접한 영역으로 한정 지어 연산량을 줄이는 최적화 기법
