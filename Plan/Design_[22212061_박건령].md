## 1. Introduction
#### Summary
본 문서는 'Net-Iocp' 프로젝트의 분석 단계를 거쳐 도출된 요구된 요구사항을 바탕으로, 시스탬의 구체적인 설계 방안을 기술한 최종 기술 설계서이다. 본설계서는 시스템의 정적 구조를 정의하는 클래스 다이어그램, 객체간의 동적 상호작용을 나타내는 시퀀스 다이어그램, 그리고 시스템의 상태 변화를 명시하는 상태 머신 다이어그램을 상세히 정의한다. 이를 통해 실제 구현 단계에서 발생할 수 있는 모호성을 제기하고, 개발자에게 명확한 구현 가이드를 제공하는 것을 목적으로 한다.

#### Introduce
본 시스템은 대규모 동시 접속자가 발생하는 환경에서도 낮은 지연 시간과 높은 처리량을 보장해야 하는 고성능 게임 서버 엔진을 지향한다. 시스템의 핵심 기술적 특징은 다음과 같다.
- **IOCP 기반 비동기 엔진**: Windows 플랫폼의 I/O 모델인 IOCP를 네트워크 최하단 계층에 배치하여 비동기 처리 성능을 극대화한다.
- **RUDP**: UDP의 빠른 전송 속도를 유지하면서도 애플리케이션 계층이ㅔ서 Reliable UDP 매커니즘을 구현하여 데이터 전송의 신뢰성을 확보한다.
- **공간 분할 최적화**: 수많ㅇ느 객체 간의 상호작용 연산 비용을 절감하기 위해 Sector 기반 공간 분할 알고리즘을 적용한다.
- **Modern C++ 표준 활용**: C++/17/20 표준의 기능을 적극 도입하여 메모리 안전성을 높이고 효율적인 동시성 제어가 가능한 아키텍처를 설계한다.

#### Goals
본 설계의 최종 목표는 고성능 및 고신뢰성을 갖춘 서버 아케틱철르 구축하는 것이며, 세부 목표는 다음과 같다.
- **구현 모호성 제거**: 분석 단계의 유스케이스를 구체적인 시퀀스 및 클래스 구조로 변환하여 설계와 구현 간의 간극을 최소화한다.
- **시스템 확장성 확보**: 비동기 엔진과 공간 분할 알고리즘을 통해 대규모 접속자 수용이 가능한 확장성 있는 구조를 설계한다.
- **안정적인 상태 관리**: 클라이언트와 서버의 복잡한 상태 변화를 상태 머신 다이어그램으로 정의하여 예외상황에서도 안정적인 서비스 유지를 가능하게 한다.
- **효율적인 자원 관리**: 최신 C++ 표준 기술을 활용하여 불필요한 자원 낭비를 줄이고 서버 운여의 효율성을 극대화한다.

## 2. Class Diagram
본 시스템은 크게 네트워크 입출력을 담당하는 ```IOCP Layer```, 세션 및 패킷 신뢰성을 관리하는 ```Session Layer```, 게임의 비즈니스 로직을 처리하는 ```Logic Layer```, 그리고 시스템의 상태를 감시하는 ```Monitoring Layer```로 계층화하여 설계되었다. 각 계층은 인터페이스를 통해 결합도를 낮추고 독립적인 테스트와 확장을 용이하게 한다.

## 3. Sequence Diagram

#### 1) 대규모 세션 접속 및 인증
## 3. Sequence Diagram

#### 1) 대규모 세션 접속 및 인증
1. **Connection Request**: `BotManager::SpawnBots()`가 호출되어 Dummy Client를 생성하고 `IocpCore`로 연결 요청을 보낸다.
2. **Accept & Alloc**: `IocpCore`는 요청을 수락하고 `ObjectPool::Alloc<RudpSession>()`을 호출하여 세션 객체를 할당한다.
3. **Register Handle**: `IocpCore::RegisterSocket()`을 통해 클라이언트 소켓을 IOCP에 등록한다.
4. **Auth Request**: Dummy Client가 `PKT_CS_AUTH_REQ` 패킷을 전송한다.
5. **Receive Event**: `IocpCore::WorkerThreadMain()` 루프에서 GQCS 이벤트를 감지하고 `RudpSession::HandleReceive()`를 호출한다.
6. **Dispatch**: `RudpSession`은 패킷 조립 후 `PacketHandler::Dispatch()`를 호출한다.
7. **Authentication Logic**: `PacketHandler`는 등록된 인증 핸들러를 실행하고, 성공 시 플레이어를 월드에 등록한다.
8. **Auth Response**: 서버가 `PKT_SC_AUTH_SUCCESS`를 클라이언트에게 전송한다.

#### 2) 실시간 위치 업데이트
1. **Move Packet Send**: Dummy Client가 위치 정보가 담긴 패킷(Unreliable)을 전송한다.
2. **IOCP Dispatch**: `IocpCore::WorkerThreadMain()`를 거쳐 `RudpSession::HandleReceive()`가 호출된다.
3. **Routing**: `PacketHandler::Dispatch()`는 패킷 타입을 확인하고 이동 로직 핸들러로 라우팅한다.
4. **Update Position**: 핸들러는 `World::GetSector(x, y)`를 호출하여 현재 섹터를 확인하고 위치를 갱신한다.
5. **Sector Check**: 섹터 변경이 발생하면 이전 섹터에서 제거하고 `NewSector::AddEntity()`를 호출한다.
6. **Broadcast**: `Sector::BroadcastInRadius()`를 호출하여 인접한 섹터의 클라이언트들에게 위치 갱신 패킷을 전송한다.

#### 3) 전투 이벤트 동기화
1. **Attack Packet Send**: Dummy Client가 공격 패킷(Reliable)을 전송하고 `TimerWheel::AddTimer()`를 통해 재전송 타이머를 시작한다.
2. **Server Processing**: 서버는 패킷을 수신하고 `PacketHandler::Dispatch()`를 통해 데미지 로직을 수행한다.
3. **Send ACK**: 서버는 수신 확인(ACK) 패킷을 송신한다.
4. **Receive ACK**: 클라이언트가 ACK를 수신하면 `RudpSession::ProcessAck()`를 호출하여 타이머를 해제한다.
5. **Timeout & Retransmit**: 지정된 시간 내에 ACK가 도착하지 않으면 `TimerWheel::Tick()`이 타임아웃 이벤트를 발생시키고 패킷을 재전송한다.

#### 4) 네트워크 장애 시뮬레이션 설정
1. **Config Request**: 관리자나 테스트 스크립트가 `NetworkLayer`에 장애 설정을 요청한다.
2. **Set Parameters**: 패킷 손실률(Loss Rate)과 지연 시간(Latency)을 설정한다.
3. **Packet Drop Simulation**: 이후 송수신되는 패킷들은 설정된 확률에 따라 폐기되거나 지연 큐에 진입한다.
4. **Monitoring**: `MetricManager`는 손실된 패킷 수를 카운팅하여 모니터링 데이터에 반영한다.

#### 5) 섹터 기반 동기화 제어
1. **Calculate Index**: 객체 좌표 $(x, y)$를 기반으로 섹터 인덱스 $Index = (y / SectorHeight) \times Width + (x / SectorWidth)$를 계산한다.
2. **Retrieve Sector**: 계산된 인덱스를 통해 해당 섹터 객체를 반환한다.
3. **Interest Management**: 섹터 및 인접 8개 섹터의 엔티티만 순회하여 연산 범위를 제한한다.
4. **Filtering**: 시야 거리(Vision Radius)를 벗어난 엔티티는 패킷 전송 대상에서 제외하여 트래픽을 최적화한다.

#### 6) 실시간 서버 메트릭 노출
1. **Event Occurrence**: 패킷 수신, 세션 접속 등의 이벤트가 발생한다.
2. **Update Metric**: 각 핸들러는 `MetricManager`를 호출하여 메트릭을 실시간으로 갱신한다.
3. **Scraping Request**: 외부 Prometheus 서버가 주기적으로 HTTP 요청을 보낸다.
4. **Expose Data**: `MetricManager::ExposeMetrics()`가 수집된 데이터를 Prometheus 표준 포맷으로 응답한다.

#### 7) 통합 대시보드 시각화
1. **Data Push**: Prometheus가 수집한 시계열 데이터를 저장한다.
2. **Query Request**: 관리자가 웹 브라우저를 통해 Grafana 대시보드에 접속한다.
3. **Visualization**: Grafana는 Prometheus에 쿼리를 보내 PPS, CPU 사용량 등의 데이터를 가져와 그래프로 렌더링한다.

#### 8) 지표 임계치 기반 알람
1. **Check Threshold**: 시스템은 주기적으로 현재 부하가 설정된 임계치를 초과했는지 확인한다.
2. **Trigger Alert**: 임계치 초과 시 알람 이벤트를 발생시킨다.
3. **Notification**: 관리자에게 이메일이나 메신저를 통해 경고 메시지를 전달한다.

#### 9) 동적 봇 행동 패턴 제어
1. **Update Loop**: `BotManager::StartSimulation()`이 매 프레임 호출된다.
2. **State Transition**: 각 Bot 객체는 자신의 FSM 상태를 확인하고 전이 조건(예: Idle → Move)을 체크한다.
3. **Action Execution**: 상태에 따라 적절한 패킷을 생성하여 전송한다.
4. **Random Pattern**: 일정 확률로 행동 패턴을 변경하여 실제 유저와 유사한 트래픽을 생성한다.

#### 10) 세션 종료 및 자원 회수
1. **Disconnect Request**: 클라이언트가 접속 종료 패킷을 보내거나 소켓을 닫는다.
2. **Event Detection**: `IocpCore` 워커 스레드에서 연결 해제 이벤트를 감지한다.
3. **Cleanup Logic**: `RudpSession`의 종료 처리를 수행하고 월드에서 해당 엔티티를 제거한다.
4. **Resource Return**: `ObjectPool::Free(session)`을 호출하여 세션 객체를 메모리 풀로 반환한다.
