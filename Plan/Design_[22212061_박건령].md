## 1. Introduction
#### Summary
본 문서는 'Net-Iocp' 프로젝트의 분석 단계를 거쳐 도출된 요구된 요구사항을 바탕으로, 시스탬의 구체적인 설계 방안을 기술한 최종 기술 설계서이다. 본설계서는 시스템의 정적 구조를 정의하는 클래스 다이어그램, 객체간의 동적 상호작용을 나타내는 시퀀스 다이어그램, 그리고 시스템의 상태 변화를 명시하는 상태 머신 다이어그램을 상세히 정의한다. 이를 통해 실제 구현 단계에서 발생할 수 있는 모호성을 제기하고, 개발자에게 명확한 구현 가이드를 제공하는 것을 목적으로 한다.

#### Introduce
본 시스템은 대규모 동시 접속자가 발생하는 환경에서도 낮은 지연 시간과 높은 처리량을 보장해야 하는 고성능 게임 서버 엔진을 지향한다. 시스템의 핵심 기술적 특징은 다음과 같다.
- **IOCP 기반 비동기 엔진**: Windows 플랫폼의 I/O 모델인 IOCP를 네트워크 최하단 계층에 배치하여 비동기 처리 성능을 극대화한다.
- **RUDP**: UDP의 빠른 전송 속도를 유지하면서도 애플리케이션 계층이ㅔ서 Reliable UDP 매커니즘을 구현하여 데이터 전송의 신뢰성을 확보한다.
- **공간 분할 최적화**: 수많ㅇ느 객체 간의 상호작용 연산 비용을 절감하기 위해 Sector 기반 공간 분할 알고리즘을 적용한다.
- **Modern C++ 표준 활용**: C++/17/20 표준의 기능을 적극 도입하여 메모리 안전성을 높이고 효율적인 동시성 제어가 가능한 아키텍처를 설계한다.

#### Goals
본 설계의 최종 목표는 고성능 및 고신뢰성을 갖춘 서버 아케틱철르 구축하는 것이며, 세부 목표는 다음과 같다.
- **구현 모호성 제거**: 분석 단계의 유스케이스를 구체적인 시퀀스 및 클래스 구조로 변환하여 설계와 구현 간의 간극을 최소화한다.
- **시스템 확장성 확보**: 비동기 엔진과 공간 분할 알고리즘을 통해 대규모 접속자 수용이 가능한 확장성 있는 구조를 설계한다.
- **안정적인 상태 관리**: 클라이언트와 서버의 복잡한 상태 변화를 상태 머신 다이어그램으로 정의하여 예외상황에서도 안정적인 서비스 유지를 가능하게 한다.
- **효율적인 자원 관리**: 최신 C++ 표준 기술을 활용하여 불필요한 자원 낭비를 줄이고 서버 운여의 효율성을 극대화한다.

## 2. Class Diagram
본 시스템은 크게 네트워크 입출력을 담당하는 ```IOCP Layer```, 세션 및 패킷 신뢰성을 관리하는 ```Session Layer```, 게임의 비즈니스 로직을 처리하는 ```Logic Layer```, 그리고 시스템의 상태를 감시하는 ```Monitoring Layer```로 계층화하여 설계되었다. 각 계층은 인터페이스를 통해 결합도를 낮추고 독립적인 테스트와 확장을 용이하게 한다.

## 3. Sequence Diagram

#### 01: 대규모 세션 접속 및 인증

<img width="971" height="554" alt="image" src="https://github.com/user-attachments/assets/d9e85242-30f9-4fe0-9c95-9b97e5c7b1e4" />

1. **Spawn Request**: `BotManager::SpawnBots()`가 호출되어 다미 클라이언트를 생성하고 서버의 UDP 포트로 접속 시퀀스를 개시한다.
2. **Session Allocation**: `IocpCore`가 수락 시, `SessionManager::CreateSession()`을 호출하고 내부적으로 `LockFreeObjectPool::Alloc()`을 통해 `RudpSession` 객체를 할당한다.
3. **Handle Binding**: `IocpCore::RegisterSocket()`을 통해 세션의 소켓 핸들을 IOCP 포트에 바인딩하여 커널 레벨의 비동기 이벤트를 활성화한다.
4. **Auth Packet Receive**: 클라이언트가 보낸 인증 패킷이 `RudpSession::HandleReceive()`를 거쳐 `PacketDispatcher::Dispatch()`에 도달한다.
5. **Job Enqueue**: 디스패처는 인증 로직을 `JobQueue::PushJob()`에 삽입하여 로직 스레드로 작업을 위임한다.
6. **Execution**: `GameLogic::Update()`에서 해당 Job을 추출하여 실행하고, 성공 시 `World::AddEntity()`를 통해 `Player` 객체를 가상 공간에 등록한다.
7. **Welcome Response**: `Player::SendPacket()`을 통해 인증 성공 패킷을 클라이언트에게 최종 전송한다.

#### 02: 실시간 위치 업데이트 및 섹터 동기화

<img width="967" height="635" alt="image" src="https://github.com/user-attachments/assets/7d0fd533-578a-4d14-ad8f-5b66ad1988db" />

1. **Move Packet**: 클라이언트가 이동 데이터를 담은 `Packet`을 전송한다.
2. **IO Processing**: `IocpCore::WorkerThreadMain()`에서 완료 통지를 감지하고 `RudpSession`의 순환 버퍼(`CircularBuffer`)에 데이터를 적재한다.
3. **Logic Dispatch**: `PacketDispatcher`는 이동 패킷임을 식별하고 이를 로직 큐에 삽입한다.
4. **Position Update**: `GameLogic` 스레드는 `Entity::SetPosition()`을 호출하여 위치를 갱신한다.
5. **Sector Cross Check**: `World::GetSector()`를 통해 이동 전후의 섹터를 비교한다. 섹터 변경 시 이전 섹터에서 `RemoveEntity()`, 새 섹터에 `AddEntity()`를 수행한다.
6. **Broadcasting**: `Sector::Broadcast()`를 호출하여 이동한 엔티티 주변 섹터에 있는 모든 `Player`들에게 위치 갱신 정보를 브로드캐스트한다.

#### 03: 전투 이벤트 동기화 및 RUDP 재전송

<img width="734" height="900" alt="image" src="https://github.com/user-attachments/assets/c0b6c481-2b76-4eb9-b591-0b70c3e481cd" />

1. **Attack Action**: 공격자가 공격 패킷을 전송한다. RUDP 신뢰성 확보를 위해 송신 측 `RudpSession`은 `m_uSequenceNumber`를 부여한다.
2. **Retransmit Timer**: 패킷 송신과 동시에 `TimerWheel::AddTimer()`를 호출하여 일정 시간 뒤의 재전송 작업을 예약한다.
3. **ACK Process**: 수신 측(서버/클라이언트)이 패킷을 정상 수신하면 ACK 번호를 담아 응답한다.
4. **Timer Cancel**: 송신 측이 ACK를 받으면 `RudpSession::ProcessAck()`를 호출하여 `TimerWheel`에 예약된 재전송 작업을 취소한다.
5. **Timeout Handling**: 만약 ACK가 유실되어 타임아웃이 발생하면, `TimerWheel::Tick()`에 의해 예약된 콜백이 실행되어 패킷을 다시 전송한다.

#### 04: 네트워크 장애 시뮬레이션 설정

<img width="726" height="813" alt="image" src="https://github.com/user-attachments/assets/f73ffe61-08b6-4b2b-96af-777ceaf2340a" />

1. **Admin Request**: 관리자 CLI를 통해 특정 손실률(Loss Rate) 파라미터를 설정한다.
2. **Filter Injection**: `RudpSession`의 송수신 단계에 장애 시뮬레이션 필터 로직이 개입한다.
3. **Simulated Drop**: 설정된 확률에 따라 `Packet` 객체를 파괴하거나 처리를 지연시켜 네트워크 불안정 상황을 모의한다.
4. **Metric Logging**: `MetricManager::RecordPacket()`은 유실된 패킷 수와 지연 시간을 기록하여 모니터링 데이터에 반영한다.

#### 05-A: 섹터 기반 동기화 범위 제어

<img width="729" height="553" alt="image" src="https://github.com/user-attachments/assets/94c131d3-f37e-40a3-b3b1-a3e2089e65ef" />

1. **Sector Query**: `GameLogic`이 특정 엔티티의 월드 좌표를 기준으로 `World::GetSector()`를 호출하여 인접한 섹터 리스트를 획득한다.
2. **Entity Iteration**: 해당 인접 섹터 내부의 엔티티들을 순회하기 위해 다중 스레드 환경에서 안전하게 읽기 락(`shared_lock`)을 획득한다.
3. **Distance Validation**: 대상 엔티티의 위치 정보(`GetPosition()`)를 조회하여, 송신자와의 거리가 시야 반경(AOI) 범위 내(within range)에 포함되는지 거리 검사를 수행한다.
4. **Async Packet Enqueue**: 거리가 유효한 대상 `Player`의 경우, 개별 세션 락(`session.lock()`)을 획득한 후 `RudpSession`을 통해 상태 갱신 패킷(`infoPacket`)을 비동기 송신 큐에 안전하게 삽입(`enqueue async send`)한다.

#### 05-B: 섹터 기반 동기화 범위 제어

<img width="727" height="586" alt="image" src="https://github.com/user-attachments/assets/06ff81f4-8045-470d-83f0-105b8e0374e7" />

1. **Sector Query & Iteration**: 05-A 과정과 동일하게 인접 섹터 리스트를 획득하고 내부 엔티티들의 위치 데이터를 읽기 락(`shared_lock`) 하에 순회한다.
2. **Out of Range Detection**: 대상 엔티티 위치(`GetPosition()`)와의 거리가 설정된 시야 반경(AOI)을 초과하는 것(out of range)으로 판별된다.
3. **Selective Skip**: 해당 엔티티에 대해서는 패킷 전송 로직을 생략(skip entity)하며, 패킷을 전송하지 않으므로 `RudpSession`에 대한 어떠한 접근이나 락 획득도 수행하지 않는다.
4. **Cost Optimization**: 이 선택적 스킵 메커니즘을 통해 서버 전체의 브로드캐스트 연산 비용을 기존 $O(N^2)$에서 $O(\text{인접 섹터} \times \text{엔티티 수})$로 대폭 절감하여 성능을 최적화한다.

#### 06: 실시간 서버 메트릭 수집 및 노출

<img width="723" height="669" alt="image" src="https://github.com/user-attachments/assets/9fa2b7bd-7559-489c-9366-ca40338a328b" />

1. **Event Trigger**: 패킷 처리, 세션 연결/해제 등의 이벤트 발생 시 `MetricManager::RecordPacket()`이 호출된다.
2. **Atomic Update**: `m_uPacketCounter` 등 원자적 변수들을 락프리 방식으로 즉시 갱신한다.
3. **Scrape Request**: 외부 모니터링 서버(Prometheus)가 HTTP 요청을 보낸다.
4. **Serialization**: `MetricManager::SerializeMetrics()`가 현재 지표 데이터를 JSON 또는 표준 포맷으로 직렬화하여 응답한다.

#### 07: 통합 대시보드 시각화 흐름

<img width="734" height="923" alt="image" src="https://github.com/user-attachments/assets/4d13c4a0-745f-4922-9b6c-9d1adb722ef8" />

1. **Data Ingestion**: Prometheus 서버가 `MetricManager`로부터 수집한 시계열 데이터를 저장한다.
2. **Dashboard Query**: Grafana 대시보드에서 PPS(Packet Per Second) 및 접속자 수 쿼리를 전송한다.
3. **Rendering**: 수집된 지표를 기반으로 서버 부하 상태를 그래프 및 차트 형태로 시각화하여 관리자에게 제공한다.

#### 08: 지표 임계치 기반 알람 알림

<img width="736" height="636" alt="image" src="https://github.com/user-attachments/assets/5562488c-97f3-49fb-8e79-77addbff2c8c" />

1. **Threshold Check**: `MetricManager`가 주기적으로 `m_fLatencyGauge` 값을 확인한다.
2. **Alarm Trigger**: 지연 시간이 설정된 임계치(예: 200ms)를 초과하면 알람 이벤트를 발생시킨다.
3. **Notification**: 관리자 터미널(`Server Console UI`)에 경고 로그를 출력하고, 외부 메신저 API 등을 통해 이상 상태를 통보한다.

#### 09: 동적 봇 행동 패턴 시뮬레이션

<img width="739" height="1002" alt="image" src="https://github.com/user-attachments/assets/58c07aac-4622-43fc-9815-e651a4727dba" />

1. **FSM Update**: `BotManager`가 관리하는 모든 `Bot` 객체의 `Update()`가 주기적으로 호출된다.
2. **State Transition**: `Bot::ChangeState()`에 의해 AI 상태(배회, 추적 등)가 전이된다.
3. **Action Packet**: 전이된 상태에 따라 `Bot`은 적절한 `Packet`을 생성하여 `IocpCore`를 통해 서버로 송신하며 실제 유저와 유사한 부하를 생성한다.

#### 10: 세션 종료 및 자원 회수

<img width="736" height="680" alt="image" src="https://github.com/user-attachments/assets/80872fc5-3845-485d-a3cc-365fc5d2b733" />

1. **Disconnect Event**: 클라이언트의 접속 종료 또는 타임아웃을 `IocpCore` 워커 스레드가 감지한다.
2. **Cleanup Job**: `SessionManager::ReleaseSession()`이 호출되어 활성 세션 맵에서 해당 ID를 제거한다.
3. **World Exit**: 로직 스레드에서 `World::RemoveEntity()`를 호출하여 엔티티 정보를 삭제하고 소속 섹터에서 제외한다.
4. **Pool Return**: 모든 참조가 해제된 후 `LockFreeObjectPool::Free()`를 호출하여 `RudpSession` 메모리 리소스를 즉시 재사용 가능한 상태로 풀에 반환한다.

## 4. State Machine Diagram

시스템 내 핵심 객체들의 라이프사이클과 상태 전이 조건을 정의한다. 특히 RUDP의 신뢰성 확보를 위한 `TimerWheel`과의 연계 동작과 `sequenceNumber` 관리를 포함하여 설계한다.

### 4.1. Client (Bot) State Machine

클라이언트(Bot)는 서버와의 네트워크 연결 상태 및 게임 로직 동기화 단계에 따라 다음과 같은 상태 변화를 거친다.

<img width="590" height="703" alt="image" src="https://github.com/user-attachments/assets/bee1be44-c967-4a8c-8415-3213dda28362" />

| State Name | Description & Transition Trigger |
| :--- | :--- |
| **연결 해제** | 시스템 초기 상태 또는 세션이 완전히 종료된 상태이다. <br> - **Transition**: `BotManager::SpawnBots()` 호출 및 소켓 생성 시 '연결 중' 상태로 전이한다. |
| **연결 중** | 서버의 UDP 포트로 접속을 시도하며 핸드셰이크를 수행하는 상태이다. <br> - **Transition**: 소켓 연결 성공 후 `PKT_CS_AUTH_REQ` 패킷 송신 시 '인증 대기' 상태로 전이한다. |
| **인증 대기** | 서버로부터 인증 승인 응답을 기다리는 논리적 연결 단계이다. <br> - **Transition**: 서버로부터 `PKT_SC_AUTH_SUCCESS` 수신 및 월드 데이터 로딩 시 '활성' 상태로 전이한다. |
| **활성** | 월드에 진입하여 `BotManager`의 AI 패턴에 따라 이동 및 전투 패킷을 송수신하는 상태이다. <br> - **Transition**: 사용자 로그아웃 요청 또는 하트비트 타임아웃 발생 시 '종료' 상태로 전이한다. |
| **종료** | 소켓 리소스를 반납하고 세션 정보를 파기하는 사후 정리 단계이다. <br> - **Transition**: 모든 자원 정리가 완료되면 다시 '연결 해제' 상태로 복귀한다. |

### 4.2. Server Session (RudpSession) State Machine

서버 세션은 `LockFreeObjectPool`에 의해 관리되며, IOCP 커널 객체 등록 및 인증 여부에 따라 엄격하게 상태가 제어된다.

<img width="451" height="619" alt="image" src="https://github.com/user-attachments/assets/f01b0c78-bbf4-4bd5-99e6-581a56a9bc22" />

| State Name | Description & Transition Trigger |
| :--- | :--- |
| **유휴 (풀)** | `LockFreeObjectPool` 내부에서 재사용을 위해 대기 중인 상태이다. <br> - **Transition**: `SessionManager::CreateSession()` 호출로 객체가 할당(`Alloc`)될 때 '수락' 상태로 전이한다. |
| **수락** | 새로운 클라이언트에게 소켓 핸들이 할당되었으나, 아직 커널 레벨의 감지가 시작되지 않은 상태이다. <br> - **Transition**: `IocpCore::RegisterSocket()` 완료 시 '연결 성립' 상태로 전이한다. |
| **연결 성립** | 네트워크 I/O가 활성화되었으며, 클라이언트의 논리적 인증 패킷을 대기하는 상태이다. <br> - **Transition**: `PacketDispatcher`를 통한 인증 Job 처리가 성공하여 `Player` 객체와 바인딩될 때 '활성' 상태로 전이한다. |
| **활성** | 정상적인 비즈니스 로직을 수행하는 상태이다. Reliable 패킷 송신 시 `TimerWheel`에 재전송 작업을 등록하며 시퀀스를 관리한다. <br> - **Transition**: 클라이언트의 연결 끊김 감지 또는 세션 강제 종료 시 '닫힘' 상태로 전이한다. |
| **닫힘** | `World::RemoveEntity()`를 호출하여 가상 공간에서 정보를 삭제하고 세션을 폐쇄하는 단계이다. <br> - **Transition**: `SessionManager::ReleaseSession()`을 거쳐 풀에 반환(`Free`)될 때 다시 '유휴' 상태로 복귀한다. |
